## D-001 · 위기 표현은 항상 규칙으로, 추천보다 먼저 검사
- 날짜: 2026-11-11 (프로토타입 v4) · 상태: **채택**
- 고려한 안: ① AI가 위기 여부까지 판단 ② 규칙으로 먼저 거르고 AI는 보조
- 결정: ②. 위기 표현 목록(`CRISIS`)을 추천보다 먼저 검사하고, 걸리면 책 대신 109 안내를 보여 준다.
- 이유: 안전 기능은 결과가 매번 같아야 하고, 네트워크나 AI 오류가 나도 동작해야 한다.

## D-002 · 공개판은 규칙 방식만, AI 탭은 프로토타입에 보존
- 날짜: 2026-11-24 · 상태: **채택**
- 배경: 프로토타입 v4의 AI 탭은 claude.ai 안에서만 동작해서 GitHub Pages에서는 쓸 수 없었다.
- 고려한 안:
  ① Firebase Cloud Functions로 Claude API 호출 (유료 요금제, API 비용, 키 관리, 호출 상한 필요)
  ② 규칙 방식만 공개하고 AI 비교는 `prototype.html`에 기록으로 남김
- 결정: ②
- 이유: 비용 없이 바로 출시해 실제 사용자 반응을 먼저 본다. "감정 못 찾음" 비율이 목표(20%)를 넘으면 그때 AI 도입 근거가 된다.

## D-003 · 입력한 문장은 저장하지 않는다
- 날짜: 2026-11-24 · 상태: **채택**
- 고려한 안: ① 문장 원문 저장 (사전 보강에 유용) ② 감정 이름, 사전 단어, 경로만 저장
- 결정: ②
- 이유: 감정 문장은 민감한 개인 정보에 가깝다. 특히 위기 표현을 저장하면 책임질 수 없는 데이터가 생긴다. 사전 보강은 "감정 못 찾음" 비율과 피드백으로 대신 판단한다.
- 대가: 어떤 문장에서 감정을 못 찾았는지 알 수 없다. 대신 테스트 케이스와 베타 테스트로 보완한다.

## D-004 · 빌드 도구 없이 HTML·CSS·JS 모듈로 구성
- 날짜: 2026-11-24 · 상태: **채택**
- 고려한 안: ① React/Vite ② 바닐라 JS ES 모듈
- 결정: ②
- 이유: 화면이 두 개뿐이고 GitHub Pages에 그대로 올릴 수 있다. 설치 없이 누구나 열어 볼 수 있다. `dist/`는 `build.ps1`로 필요한 파일만 복사해 만든다.

## D-005 · 운영자 권한은 Firestore `admins` 컬렉션으로 판단
- 날짜: 2026-11-24 · 상태: **채택**
- 고려한 안: ① 운영자 화면에 비밀번호 하드코딩 ② Firebase Auth + `admins/{uid}` 문서 존재 여부
- 결정: ②
- 이유: ①은 소스에 비밀번호가 노출된다. ②는 보안 규칙에서 서버가 직접 확인하므로 화면 코드를 고쳐도 데이터를 읽을 수 없다. 운영자 추가는 Firebase 콘솔에서만 가능하다.

## D-006 · 감정 단어에 과거형 추가
- 날짜: 2026-11-24 · 상태: **채택**
- 배경: 테스트에서 첫 화면 예시인 "요즘 너무 지쳤어"가 감정을 찾지 못했다. 사전에 "지쳐, 지친"만 있고 "지쳤"이 없었다.
- 결정: 지쳤, 슬펐, 화났, 떨렸, 신났, 기뻤, 설렜, 그리웠, 멍해를 추가했다.
- 이유: 사람들은 지난 일을 과거형으로 말하는 경우가 많다. 어간만 넣는 방식은 받침이 바뀌는 활용형을 놓친다.

## D-007 · 공유 링크는 문장이 아니라 감정 이름만 담는다
- 날짜: 2026-11-24 · 상태: **채택**
- 결정: 공유 링크는 `?emo=불안&utm_source=share` 형태로 만든다.
- 이유: 친구에게 보내는 링크에 내 속마음 문장이 그대로 들어가면 공유하기 꺼려진다. 감정 이름만 있어도 같은 책 3권을 보여 줄 수 있다.
